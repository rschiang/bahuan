# Decisions

Plans, rationale and choices for Bahuan. The README stays short; this file
holds the reasons.

## Goals

- Bring back the blobs, mixing Android 6 and 7.x.
- Prefer flat designs: the Android 7.x objects and the Android 12 refresh.
- Never use the bordered Android 8–11 style or Noto 3D, unless nothing else
  exists for an emoji.
- Keep the Android 7.1 waved flags, using the `waveflag` mesh warp.
- Use a current toolchain: COLRv1, CBDT, sbix and OpenType-SVG, built and
  released by CI.

## Settled

| Topic | Decision |
|---|---|
| Name | The font is **Bahuan**. The selection tool is **`steamer`**. |
| Starting point | A brand-new, empty repo. Copy upstream's **current** build tooling; don't re-port legacy scripts. |
| Era labels | Android versions only name an era. We **don't** check them against the fonts Android actually shipped. |
| Emoji newer than the blobs (Emoji 5.0+) | Fall back to Google's own newer designs, preferring the newest flat (Android 12+) version. Anything still bordered goes to a redraw backlog. |
| How styles are chosen | Per Unicode **subgroup** (about 100 of them, from `emoji-test.txt`), with overrides for single emoji. No default style is fixed in advance; pick whatever is most harmonious. |
| Manifest format | Compact `subgroup = era` and `key = era` tables. Reasons go in inline comments. |
| Docs | `README.md` stays short. Plans, rationale and choices go in `DECISIONS.md`. |
| Licenses | Code and art under Apache-2.0, fonts under OFL-1.1. Keep Google's attribution. Don't use "Noto" in the name (it's Google's trademark). |

## Upstream

Build tooling in `build/` is adapted from
[googlefonts/noto-emoji](https://github.com/googlefonts/noto-emoji) at
`e20cbc2bbec1926686be9f9bee7d1d2cfa1fea0e` (main, 2026-09-24, Unicode 18.0).
`sources/emoji-test.txt` is pinned to Emoji 18.0.

## Era catalog

`sources/eras.toml` maps each era to an upstream commit. `steamer fetch`
checks each one out as a sparse worktree of a blob-less clone, renames files
to keys (`1f469_200d_1f52c`, FE0F dropped), applies that era's
`emoji_aliases.txt`, renders 72px and 512px PNGs with resvg, and writes
`sources/<era>/index.json`.

| Era | Commit | Masters | Emoji | Why it's here |
|---|---|---|---|---|
| `android-6.0.1` | `343e9ff` (2016-03) | PNG only | 1049 | Classic blobs. `svg/` then still held 2014 drawings. |
| `android-7.0` | `a5ff5e0` (2016-06) | PNG only | 1536 | Nougat people and skin tones, blob faces. |
| `android-7.1` | `e456654` (2017-07) | SVG | 2123 | Last blobs; the 2017-05 SVGs are the only vector blobs. |
| `android-8.0` | `v2017-09-13-design-refresh` | SVG | 2382 | Bordered style. Avoided, reference only. |
| `android-11` | `v2020-09-16-unicode13_1` | SVG | 3271 | Last bordered snapshot; tells which designs the 2021 refresh skipped. Avoided. |
| `android-12` | `v2.028` (2021-07) | SVG | 3271 | The flat refresh. |
| `android-16` | `v2.051` (2025-09) | SVG | 3682 | Emoji 17 update: the 2021-lineage art as it stood before the 2026 redraw. |
| `latest` | `e20cbc2` (2026-09) | SVG | 3963 | Newest designs, Emoji 18.0. |
| `waveflag` | `e20cbc2` region-flags | SVG | 262 | Generated by `flags/waveflag.py`. |

"Emoji" counts fully-qualified Emoji 18.0 entries the era covers. Picks from
the PNG-only eras can feed CBDT and sbix only; vector formats need a vector
era behind them (see `steamer report`).

`android-16` is the 2025 release (upstream `v2.051`, Emoji 17; Android 16's
feature drop, not "Android 17", which is the 2026 line `latest` sits on). It
is a comparison column, not a default: nothing in `selection.toml` names it
yet, so `resolved.tsv` is unchanged. Against the current picks it offers
different art for 291 of 3963 — 48 of the 504 `latest` picks (31 of them the
round fallback faces: 🥺 🥰 🤩 🥳 …, plus 🦋 🪞 🪧 🛜 🪸) and 243 `android-12`
picks (168 `person-role`, 24 `person-fantasy`, 18 each `person-activity` and
`person-resting`). It does **not** fix the bordered-art problem: 1562 of its
own masters are still byte-identical to `android-11`.

## Selection

`selection/selection.toml` picks an era per Unicode subgroup, with a few
single-emoji overrides. `steamer resolve` applies it to every fully-qualified
entry of `sources/emoji-test.txt` and writes `selection/resolved.tsv`
(committed, so selection changes show up as diffs).

- Order: override → subgroup → `fallback` (`android-12`, then `latest`) →
  `avoid` (`android-8.0`, `android-11`). A subgroup value may be a list,
  tried in order before the fallback.
- **Family rule.** Skin-tone and gender variants follow their base's era when
  that era has the whole family. Otherwise the family moves down the chain
  together. Overriding a base covers its variants.
- **Unchanged bordered art is skipped.** The 2021 refresh left many files
  byte-identical to the bordered `android-11` ones. During the fallback, such
  a file is skipped when a later fallback era has newer art. Where the 2020
  art is fine but `latest` is worse (people, animals, family keycap tiles),
  the subgroup pins `["android-7.1", "android-12"]`.
- Picks from PNG-only eras still need a vector master for COLRv1 and SVG;
  `resolved.tsv` names the vector era behind them. The current draft has
  none.

### How the draft was made

`steamer sheets` drew one contact sheet per subgroup (eras as columns). Ten
subagents scored the eras for about ten related subgroups each, against this
rubric: blob or flat; no outline or border; flat fills, except blob shading;
consistent within and across neighboring subgroups; legible at 20px; a
vector master exists. Their shortlists are in `selection/shortlist/`. A
consolidation pass wrote the manifest and listed open calls in
`selection/shortlist/REVIEW.md`.

Draft result (3963 emoji): `android-7.1` 1630, `android-12` 1567, `latest`
504, `waveflag` 262. Seven overrides, 38 redraw items, no avoided eras used.

- Smileys, hands, body parts, people, animals, places, transport, objects and
  symbols: `android-7.1`.
- Food, drink, plants, `person-role`, `person-fantasy`, `person-symbol`,
  `medical`, `household`: `android-12`.
- Notable overrides: 🔫 `android-12` (7.1 is a revolver), ✅ `android-12`
  (7.1's tick vanishes at 20px), 🗾 `android-12`, 🦋 `latest` (keeps it
  apart from the new monarch), 🧐 🫖 🪞 `latest`.

Owner review is pending. The gallery (`steamer gallery`, published as a
private Claude Artifact) takes clicks per subgroup or emoji; `steamer
import-gallery choices.json` writes them back with comments kept.

### Emoji newer than the blobs

Emoji 5.0 and later fall back to Google's own newer designs, newest flat
first. Faces fall back to `latest`'s round flat faces (🥺 🥰 🥳 …): not
bordered, but the most visible seam, and the first candidates for blob
redraws.

### Redraw backlog

`[redraw]` in the manifest is the backlog of emoji with no acceptable era and
no recipe; it is empty. The former 38 were closed three ways:

- **Derived art** (39 recipes, 19 of them backlog entries): `art/recipes.toml`
  recolours, strips layers from, re-fills and composes upstream masters;
  `steamer redraw` writes `art/derived/` (generated, git-ignored). Ops are
  `drop` (delete elements by fill), `subpath` (keep one subpath of each path,
  which separates an Illustrator frame from its cut-out), `recolor`, `fill`
  (paint what would default to black) and `[[<key>.add]]` (draw another master
  on top, optionally scaled about the canvas centre). Every heart is the 💛
  `1f49b` silhouette — the standard-size one — in the Android 16 colours;
  circles and squares share one hue per colour name, and every black shape
  (⚫ ⬛ ◼️ ◾ ▪️) keeps its design on the Android 16 `#424242`, which holds
  contrast on dark backgrounds, matching 🔲 in 7.1; ❓❗ ‼️ ⁉️ go from the 7.1
  blue to red and ❔❕ darken to `#BDBDBD` to read at 20px; ✅ is ❎'s frame in
  the Android 16 green with the 7.1 tick composed on top, so the pair mirrors;
  the four family keycap tiles become blue busts. 🟰 and 🫟 are a de-gloss
  trial: Android 16 art whose only objection was the highlight layer, kept as
  drawn with the glints (and 🫟's clipped shading) dropped. A recipe changes
  the art, never the era a key resolves to; PROVENANCE `fixups` names the donor
  (`derived:<era>:<key>`).
- **Generated flags**: 🏳️‍⚧️ 🏴‍☠️ come from `flags/extra/` through
  `waveflag.py`. The twelve hand-drawn 7.1 country flags are preferred over
  the mesh-warped ones (`country-flag = ["android-7.1", "waveflag"]`); the
  heavier outline is an accepted seam.
- **Accepted as-is** (17): ❤️‍🔥 ❤️‍🩹 🦾 🦿 🧠 🫀 🫁 🦷 🪄 🪆 🪢 🪗 🪙 🩸 🩺 🪟 🪦 are
  2020 flat art with soft gradients that read at 20px; nothing better exists.

`steamer report` also lists art still unchanged since `android-11`. Hand-fixed
SVGs go in `art/fixes/emoji_u<key>.svg` and win over both upstream and recipes.
`steamer sheets --group NAME` renders the key groups in `selection/groups.toml`
for cross-subgroup design questions.

## Art

`steamer materialize` copies each pick's master into `art/svg/` (generated,
git-ignored) and writes `art/PROVENANCE.tsv`: era, upstream commit, path,
blob sha and fixups. Old blob SVGs are Illustrator exports. 51 of the 54 that
picosvg rejects only need their `<style>` classes inlined (`steamer/
fixups.py`); if a master still fails, the next vector era in its chain is
used and the provenance says so.

## Flags

`flags/waveflag.py` ports [rschiang/waveflag](https://github.com/rschiang/waveflag)
(the Android 7.1 look) to vectors. The C tool texture-maps a flag through a
cairo mesh patch whose corner colors encode (u, v). That makes the warp a
Coons patch: two cubic edges (the mesh points) and two straight ones. The
port pushes each region-flags path through the same patch, subdividing and
refitting segments as cubics from the patch's Jacobian, and clips to the
same rounded wave outline. The border (luminosity stroke) and the shade
(soft-light mesh, drawn as 32 bands of constant u+v) follow the C code.

- `flags/out/full/` keeps the blend modes and matches the C output within a
  median 0.4% mean pixel difference.
- `flags/out/svg/` is what the fonts use. picosvg and the font formats have
  no blend modes, so the shade becomes faint plain-alpha bands (median 1.2%).
  COLRv1 could get the exact soft-light via `PaintComposite`, as upstream's
  `colrv1_add_soft_light_to_flags.py` does for its flags; not done yet.
- Golden test: `tests/test_waveflag.py` builds against the C tool
  (`flags/waveflag.c`, from rschiang/waveflag@71efca4) for every emoji flag.
- Sources are the current region-flags SVGs vendored in noto-emoji main, so
  new flags are covered. Wikipedia-style SVGs get their units, `<switch>`
  and `<foreignObject>` normalized first.

## Build

`make` runs: `steamer resolve` → `waveflag.py` → `steamer materialize` →
`build/generate_configs.py` (one nanoemoji config per format) → nanoemoji →
`build/postproc.py` → `build/web.py`.

| Output | nanoemoji format | For |
|---|---|---|
| `Bahuan-COLRv1.ttf` | `glyf_colr_1` | Chrome, Edge, Firefox, Windows 11 |
| `Bahuan-CBDT.ttf` | `cbdt` | Android, Linux/fontconfig |
| `Bahuan-sbix.ttf` | `sbix` | macOS and iOS |
| `Bahuan-SVG.ttf` | `picosvg` | Firefox, Safari, Adobe apps (`.ttf`: nanoemoji's OT-SVG needs glyf, not CFF) |
| `Bahuan-COLRv1*.woff2`, `bahuan.css` | subsets of COLRv1 | web |

Upstream builds CBDT with its legacy PNG pipeline and copies names and
vertical metrics from it into COLRv1. Here every format comes from
nanoemoji, so `postproc.py` sets names, the VS16 cmap (from emoji-test.txt
rather than nototools), blank tag glyphs, vhea/vmtx, `fsType = 0` and the
version on each font directly. The legacy-Android PUA mapping and upstream's
unknown-flag fallback are left out.

The build needs **GNU make 4.x**: parallel runs set `--output-sync=target`, so
a failing step's error can't scroll past behind another job's output, which is
how a broken parallel build went unnoticed once. The Makefile stops with a
message on anything older. macOS ships 3.81, so there `brew install make` and
build with `gmake`. CI is Linux only (`ubuntu-24.04`, make 4.3), so the macOS
path is checked by hand, not by a runner. Steps that write a directory rather
than one file are keyed on `.stamp` sentinels. `VERSION` (and the release tag)
is `MAJOR.MINOR`: it becomes the font revision, which is a number, so
`postproc.py` rejects anything else.

## QA

CI (`.github/workflows/ci.yml`) runs on every push and pull request: lint
and `resolve --check`, unit tests, the waveflag golden test, the build,
`make coverage` (HarfBuzz must shape every fully-qualified emoji-test
sequence to one glyph, FE0F included), `make qa` (the fontbakery checks that
apply to emoji fonts), and Playwright screenshots in Chromium and Firefox,
uploaded as artifacts. A `v*` tag also publishes a GitHub Release with the
fonts and deploys the gallery to GitHub Pages.

First local build (4 cores, ~30 minutes): all four fonts shape 3963/3963
sequences, fontbakery has no failures, and Chromium renders blob 😀, flat 🍊
and a waved 🇹🇼 from the COLRv1, CBDT and sbix builds. Chromium has no
OpenType-SVG support, so the SVG build is only seen in Firefox (CI).

macOS check of the sbix build: registered with `CTFontManagerRegisterFontsForURL`
and drawn with `CTLineDraw` — the CoreText path TextEdit and Safari use. The
family resolves to `Bahuan-sbix` with no fallback run, and 😀 🍊 🇹🇼 👍🏽 come
out blob, flat, waved and skin-toned.
